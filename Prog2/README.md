# Практическая работа № 2. Вариант 19

Консольный визуализатор зависимостей пакетов Ubuntu. Утилита читает бинарный
индекс APT по HTTP(S) или локальный тестовый граф, строит граф рекурсивным
DFS и выводит PlantUML, PNG и, по настройке, ASCII-дерево. Для поиска
зависимостей используется только стандартная библиотека Python.

## Запуск

Нужен Python 3.10 или новее. Сборка и установка Python-библиотек не
требуются. Выполняйте команды из корня репозитория.

```sh
sh Prog2/run.sh --puml-only Prog2/examples/test.yaml
sh Prog2/run.sh --reverse Prog2/examples/test.yaml
python3 -m unittest discover -s Prog2/tests -v
```

Для PNG используйте установленный `plantuml` или Java и локальный
[файл PlantUML JAR](https://plantuml.com/download). Утилита использует
встроенный движок Smetana, поэтому отдельный Graphviz для примеров не нужен.

```sh
export PLANTUML_JAR=/путь/к/plantuml.jar
sh Prog2/run.sh Prog2/examples/test.yaml
```

По умолчанию файлы сохраняются в `Prog2/out/`, а PNG открывается системным
просмотрщиком (macOS или Linux с графической сессией). Поддерживаются
`--output-dir ПАПКА`, `--no-open` для запуска без просмотрщика и
`--puml-only` для получения только исходника диаграммы. `--reverse` печатает
обратные зависимости. Скрипт принимает `PYTHON` с путём к интерпретатору.

## Конфигурация YAML

| Ключ | Значение |
| --- | --- |
| `package` | Имя пакета APT или имя из заглавных латинских букв в тестовом режиме. |
| `repository` | HTTP(S) URL индекса или путь к тестовому файлу относительно YAML. |
| `test_mode` | `true` для локального файла, `false` для Ubuntu. |
| `version` | Точная версия пакета в кавычках. |
| `ascii_tree` | `true` включает ASCII-дерево. |
| `exclude` | Подстрока имени исключаемых пакетов с учётом регистра. `""` отключает фильтр. |

Поддерживается плоский YAML из шести обязательных ключей в UTF-8. Один
параметр на строку, без отступов. Допустимы комментарии и обычные строки,
а также одинарные и двойные кавычки. Двойные кавычки используют
экранирование JSON. Пишите логические значения без кавычек. Дубликаты
и лишние ключи считаются ошибками. Ошибки конфигурации, индекса, графа
или рендеринга печатаются в stderr с кодом 1. Тест
`test_cli_rejects_each_invalid_option` демонстрирует диагностику всех шести
параметров.

## Индекс Ubuntu

`repository` указывает непосредственно на бинарный индекс `Packages`,
`Packages.gz` или `Packages.xz` одного выпуска, компонента и архитектуры
Ubuntu. Программа сама разбирает записи индекса и выбирает корневой пакет
по точному совпадению имени и версии. При отсутствии версии сообщает,
какие версии нашлись.

Граф строится из `Pre-Depends` и `Depends`. Он включает все объявленные
альтернативы и подходящих поставщиков виртуальных пакетов из `Provides`.
Для каждого имени выбирается самая новая версия в индексе, удовлетворяющая
ограничению ребра. Версии сравниваются по правилам Debian. Явные архитектуры
сверяются с полем `Architecture` кандидата, а `:any` и `:native` ищутся в том
же индексе. Недоступные в индексе варианты помечаются `[unresolved]`.
Граф описывает зависимости в одном индексе. План установки APT зависит также
от состояния системы, приоритетов, конфликтов и Multi-Arch.

Лимиты входа составляют 16 КиБ для YAML, 1 МиБ для тестового файла и
64 МиБ для индекса до и после распаковки. Граф ограничен 500 вершинами,
2500 рёбрами и глубиной рекурсии 200. Рендерер ограничен 45 секундами.

## Тестовый граф и обратные зависимости

Формат `examples/graph.txt` — одна запись `ИМЯ: ЗАВИСИМОСТЬ ...` на строку.
Имена состоят из заглавных латинских букв, версия всех пакетов — `1.0`.
У листа после двоеточия пусто. Объявляйте все вершины, в том числе листья.
Текст после `#` считается комментарием.

- `A → B → D → A` образует цикл. ASCII-дерево показывает `[cycle]`.
  `B` и `C` используют общую вершину `D`, поэтому повторная ветка
  отмечена `[seen]`. Фильтр исключает `SKIP` и обрывает путь к `HIDDEN`.
- `--reverse` разворачивает рёбра и использует тот же рекурсивный DFS.
  Для `A` прямые обратные зависимости — `D` и `TOP`, транзитивные —
  `B` и `C`. Если задать `exclude: "TOP"`, останется ветка через `D`.
- Чтобы проверить граф из одной вершины, поменяйте `package` на `ISLAND`.
  Для этой вершины обратных зависимостей тоже нет.

## Визуализация трёх пакетов и сравнение с APT

```sh
for pkg in mawk grep ubuntu-keyring; do
    sh Prog2/run.sh --no-open "Prog2/examples/$pkg.yaml"
done
```

Использован базовый индекс Ubuntu 24.04 LTS (noble), `main`, `amd64`.
Оба инструмента получили один и тот же индекс
(`SHA-256 e0d7e4cbb09d2aa7f9e104a1488817417bc9d85f3e5d9a21156a52ec641ae531`).
APT 2.8.3 запускался в Ubuntu 24.04 с пустым статусом установленных
пакетов. При сравнении имена вершин PlantUML нормализованы до имён пакетов.

| Пакет | Прямые обязательные зависимости | Обязательные рёбра в обоих графах | Дополнительные рёбра в APT |
| --- | --- | ---: | ---: |
| `mawk=1.3.4.20240123-1build1` | `libc6` | 4 | 18 |
| `grep=3.11-4build1` | `libc6`, `libpcre2-8-0` | 6 | 19 |
| `ubuntu-keyring=2023.11.28.1` | нет | 0 | 1 |

Совпали все обязательные рёбра, включая цикл `libc6 ↔ libgcc-s1`.
[apt-cache dotty](https://manpages.ubuntu.com/manpages/noble/en/man8/apt-cache.8.html)
рисует также несовместимости. Например, у `grep` есть `Conflicts: rgrep`,
а у `ubuntu-keyring` — `Breaks: ubuntu-cloudimage-keyring (<< 2018.02.05)`.
Эти поля объясняют дополнительные зелёные рёбра APT. Синие рёбра APT
обозначают `Pre-Depends`, в PlantUML для всех обязательных рёбер
используется один вид стрелки.

Чтобы воспроизвести сравнение на Ubuntu, запустите команды ниже. Они
загружают тот же публичный индекс в отдельный каталог и используют его
вместо системного кеша APT.

```sh
work=$(mktemp -d)
mkdir "$work/lists"
index=archive.ubuntu.com_ubuntu_dists_noble_main_binary-amd64_Packages.gz
curl -fsSL https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz \
    -o "$work/lists/$index"
printf '%s\n' 'deb [arch=amd64] https://archive.ubuntu.com/ubuntu noble main' \
    > "$work/sources.list"
for pkg in mawk grep ubuntu-keyring; do
    apt-cache -o APT::Architecture=amd64 \
        -o Dir::Etc::sourcelist="$work/sources.list" -o Dir::Etc::sourceparts=- \
        -o Dir::State::Lists="$work/lists" -o Dir::State::status=/dev/null \
        -o Dir::Cache::pkgcache= -o Dir::Cache::srcpkgcache= \
        dotty "$pkg" > "$work/$pkg.dot"
done
printf 'Графы APT: %s\n' "$work"
```

## История этапов

`git log --oneline -- Prog2` показывает пять этапов отдельными коммитами.
На этапе 1 приложение печатает конфигурацию как `ключ: значение`, на
этапе 2 — исходные строки прямых зависимостей. На этапе 3 оно выводит
граф после DFS, на этапе 4 добавляется `--reverse`, на этапе 5 — PlantUML,
PNG и ASCII-дерево.
