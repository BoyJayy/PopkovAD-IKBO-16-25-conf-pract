# Практическая работа № 2. Вариант 19

Консольный визуализатор зависимостей пакетов Ubuntu на Python 3.10+.
На этапе 1 программа читает конфигурацию и печатает её в формате
`ключ: значение`. Сборка и установка Python-библиотек не требуются.

```sh
sh Prog2/run.sh Prog2/examples/mawk.yaml
python3 -m unittest discover -s Prog2/tests -v
```

| Ключ | Значение |
| --- | --- |
| `package` | Имя пакета APT или имя из заглавных латинских букв в тестовом режиме. |
| `repository` | HTTP(S) URL индекса или путь к тестовому файлу относительно YAML. |
| `test_mode` | `true` для локального файла, `false` для Ubuntu. |
| `version` | Точная версия пакета, строка в кавычках. |
| `ascii_tree` | `true` включает вывод ASCII-дерева. |
| `exclude` | Подстрока имени исключаемых пакетов. `""` отключает фильтр. |

Поддерживается плоский YAML из шести обязательных ключей в UTF-8. Один
параметр на строку, без отступов. Допустимы комментарии и строковые значения
без кавычек или в одинарных/двойных кавычках. Пишите логические значения без
кавычек. Дубликаты и лишние ключи считаются ошибками. Ошибка конфигурации
печатается в stderr с кодом завершения 1.

## Этап 2. Индекс Ubuntu

`repository` указывает непосредственно на бинарный индекс `Packages`,
`Packages.gz` или `Packages.xz` одного выпуска, компонента и архитектуры
Ubuntu. В примере используется Ubuntu 24.04 LTS (noble), `main`, `amd64`.
Программа скачивает индекс по HTTP(S), самостоятельно читает его записи
и выбирает пакет по точному совпадению имени и версии. Она извлекает
обязательные зависимости из `Pre-Depends` и `Depends`, сохраняя версии,
альтернативы и строки продолжения. При отсутствии версии сообщает,
какие версии нашлись в указанном индексе.

## Этап 3. Рекурсивный DFS

```sh
sh Prog2/run.sh Prog2/examples/test.yaml
```

Тестовый файл содержит по одной записи `ИМЯ: ЗАВИСИМОСТЬ ...` на строку.
Имена состоят из заглавных латинских букв. У всех тестовых пакетов версия
`1.0`. Для листа после двоеточия ничего не пишется. Все вершины должны
быть объявлены. Текст после `#` считается комментарием.

В примере `A → B → D → A` образует цикл, а `B` и `C` используют общую
зависимость `D`. DFS хранит уже посещённые версии, оставляет рёбра цикла
и раскрывает общую вершину один раз. Фильтр исключает `SKIP` и обрывает
путь к `HIDDEN`. Поменяйте `package` на `ISLAND` для графа из одной вершины
или очистите `exclude`, чтобы увидеть отфильтрованную ветку.

Для Ubuntu граф включает все объявленные альтернативы, в том числе
доступных поставщиков виртуальных пакетов из `Provides`. Для каждого
имени выбирается самая новая версия из индекса, удовлетворяющая условию
ребра. Версии сравниваются по правилам Debian. Явная чужая архитектура
даёт неразрешённую вершину. Квалификаторы `:any` и `:native` ищутся в
том же индексе. Неразрешённые имена показаны как листья. Результат описывает
зависимости в одном индексе и не моделирует план установки APT с учётом
установленных пакетов, приоритетов, конфликтов и Multi-Arch.

## Этап 4. Обратные зависимости

```sh
sh Prog2/run.sh --reverse Prog2/examples/test.yaml
```

Утилита разворачивает рёбра и повторно использует рекурсивный DFS.
Для `A` непосредственные обратные зависимости — `D` и `TOP`.
Через `D` находятся `B` и `C`, а затем обход встречает цикл через `B`.
С `exclude: "TOP"` остаётся только ветка через `D`. Для `ISLAND`
обратных зависимостей нет. Режим использует те же правила фильтрации
и разрешения версий, что и прямой граф.
