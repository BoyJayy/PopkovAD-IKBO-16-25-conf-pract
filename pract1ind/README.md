# Индивидуальное задание: вариант 19

## Общее описание

Реализованы этапы 1 (REPL), 2 (конфигурация) и 3 (VFS) варианта 19.
Консольный эмулятор оболочки на Python 3.10+ без внешних зависимостей.
Приглашение `username@hostname:~$ ` использует данные реальной ОС.
Команды `ls` и `cd` являются заглушками: выводят имя и список аргументов.
VFS загружается из директории на диске и хранится в памяти.
Текущая директория пока не изменяется: логика `ls` и `cd` относится к этапу 4.

## Запуск и проверки

Из папки `pract1ind`:

```sh
sh run.sh
python3 -m unittest discover -s tests -v
```

Сборка не требуется. Завершение: `exit` или конец ввода (Ctrl+D).
Ctrl+C отменяет текущий ввод и оставляет эмулятор работающим.

## Этап 2. Конфигурация

| Параметр | Значение | По умолчанию |
| --- | --- | --- |
| `--vfs PATH` | Директория для загрузки VFS в память | Пустая VFS |
| `--prompt TEXT` | Точный текст приглашения, включая пробелы | Данные ОС |
| `--startup-script PATH` | Файл команд в UTF-8 | Не задан (`null`) |
| `--help` | Справка о запуске | Выход после справки |

При обычном запуске строка `[config]` показывает все три параметра и
итоговое приглашение. Значения сериализуются в JSON. Пустое приглашение
`--prompt ''` разрешено. Пути с пробелами передавайте в кавычках.
Относительные пути отсчитываются от текущей директории запуска.
На этапе 2 путь VFS только сохранялся в конфигурации. Начиная с этапа 3
директория читается в память до исполнения стартового скрипта.

```sh
sh run.sh --vfs examples/vfs/several --prompt 'student$ ' \
  --startup-script examples/success.txt
```

Команды стартового скрипта исполняются по порядку. Каждая строка
показывается с приглашением, затем выводится результат или ошибка
с именем файла и номером строки. После ошибочной строки выполнение
продолжается. `exit` завершает приложение, оставшиеся строки не исполняются.
Если скрипт закончился без `exit`, запускается REPL. Пустые строки допустимы.
Строки с `#` не являются комментариями: их поддержка вариантом 19 не требуется.

Нечитаемый файл, каталог вместо файла или неверная кодировка дают
сообщение об ошибке и код завершения 1. Ошибки команд скрипта пропускаются
и сами по себе не меняют код завершения. Обычный выход даёт код 0.
Ошибки параметров запуска дают код 2 и справку об использовании.

Два скрипта реальной ОС (POSIX sh, подходят для macOS и Linux):

```sh
sh scripts/demo_success.sh
sh scripts/demo_errors.sh
```

В каждом есть вызов эмулятора со всеми тремя параметрами. Первый также
проверяет запуск по умолчанию, переменные и кавычки. Второй демонстрирует
продолжение после ошибок, завершение через `exit`, отсутствующий файл
скрипта и неизвестный параметр CLI. Ожидаемые ненулевые коды проверяются.

## Этап 3. VFS

Источник VFS - обычная директория реальной ОС. При запуске приложение
обходит её один раз и создаёт независимый снимок в памяти: словарь
`виртуальный путь -> bytes` для файлов и `виртуальный путь -> None`
для каталогов. Корень исходной директории отображается на `/`.
Байты файлов читаются без декодирования, поэтому поддерживаются и текст,
и двоичные данные. Скрытые файлы, пустые каталоги, русские имена
и имена с пробелами сохраняются.

После загрузки операции с VFS используют этот словарь. Исходные файлы
не изменяются, ничего не распаковывается и не сохраняется обратно.
Последующие изменения источника на диске не меняют снимок.
Конфигурация и стартовый скрипт читаются отдельно как входные данные.

Если `--vfs` не указан, создаётся пустая VFS с корнем `/`.
В строке `[vfs]` выводятся число каталогов (включая корень), число файлов
и суммарный размер содержимого в байтах.

Для демонстрации загрузки добавлена служебная команда `vfs-info [путь]`:

```sh
sh run.sh --vfs examples/vfs/deep --prompt 'vfs$ '
```

Внутри эмулятора:

```text
vfs-info
vfs-info /level1/level2/level3
vfs-info /level1/level2/level3/data.txt
vfs-info /not-found
exit
```

Для каталога команда показывает имена непосредственных детей, для файла -
его виртуальный путь и размер. Данные берутся только из памяти.
Пути абсолютные либо относительно виртуального корня; `.` и `..`
нормализуются внутри `/` и не обращаются к реальной ОС.
Слишком много аргументов и отсутствующий путь дают ошибку команды.

Отсутствующий источник, файл вместо директории, недоступные для чтения
данные и специальные файлы дают ошибку загрузки VFS и код завершения 1.
Символические ссылки отклоняются, чтобы не следовать за пределы источника
и не зациклить обход. Большие источники должны помещаться в оперативной памяти.

Примеры источников находятся в `examples/vfs/`:

- `minimal/`: один файл в корне; пустая VFS также проверяется тестами.
- `several/`: несколько файлов, включая скрытый и русское имя с пробелами.
- `deep/`: файл в `level1/level2/level3/`, три уровня вложенных каталогов.

Два скрипта реальной ОС проверяют все три варианта:

```sh
sh scripts/demo_vfs.sh
sh scripts/demo_vfs_errors.sh
```

Второй дополнительно показывает пустую VFS и ошибки источника.
Оба запускают `examples/stage3.txt`: все команды этапов 1-3, режимы
заглушек, раскрытие переменных, сведения о VFS и обработку ошибок.
Часть путей есть только в конкретном примере: их отсутствие в остальных
VFS ожидаемо показывает ошибку и продолжение скрипта. Команда `exit`
проверяется в конце, строка после неё не исполняется.

Автоматические тесты проверяют также двоичные данные, сохранность
источника, независимость снимка после изменения и удаления исходных файлов,
отсутствие чтения с диска при работе команд VFS, ссылки и ошибки доступа.

## Команды и парсер

- `ls [-a] [-l] [путь ...]`: заглушка, также принимает `-al`, `-la`.
  `--` завершает обработку опций.
- `cd [путь]`: заглушка, не более одного аргумента; опций нет.
- `exit`: завершает эмулятор; аргументов нет.
- `vfs-info [путь]`: служебная команда просмотра загруженной VFS.
- Пустой ввод пропускается. Неизвестные команды, опции, лишние аргументы
  и незакрытые кавычки сопровождаются сообщением `Ошибка:`.
- `$NAME` и `${NAME}` раскрываются из окружения реальной ОС.
  Неопределённая переменная даёт пустую строку. Одинарные кавычки
  запрещают раскрытие, двойные разрешают. Обратная косая черта
  экранирует следующий символ вне одинарных кавычек.
- Значение переменной сохраняется одним аргументом, даже с пробелами.
  Подстановка команд, конвейеры, перенаправления и glob не реализованы.
Команды реальной ОС не исполняются.

## Демонстрация в интерактивном режиме

Запустите `sh run.sh`, затем введите:

```text
ls
ls -al "$HOME"
cd ${HOME}
cd 'папка с пробелами'
ls '$HOME'
unknown
cd first second
ls -z
cd "незакрытая кавычка
exit extra
exit
```

Успешные команды покажут разобранные аргументы. Ошибки не завершают REPL.
Имя пользователя, хост и значение HOME зависят от ОС запуска.

## Функции исходного кода

- `parser.read_variable`: читает значение переменной и новую позицию.
- `parser.parse_command`: разбирает строку на команду и аргументы.
- `shell.default_prompt`: формирует системное приглашение.
- `shell.validate_arguments`: проверяет аргументы команд.
- `shell.execute`: выполняет заглушку или сигнализирует завершение.
- `shell.repl`: ведёт диалог, обрабатывает ошибки и завершение ввода.
- `main.main`: запускает приложение.
- `config.parse_config`: разбирает параметры командной строки.
- `config.print_config`: выводит настройки и возвращает приглашение.
- `startup.run_startup`: исполняет строки скрипта с обработкой ошибок.
- `vfs.load_entries`: обходит источник и читает файлы в память.
- `vfs.VirtualFileSystem.load`: создаёт пустую VFS или загружает директорию.
- `vfs.VirtualFileSystem.resolve`: разрешает виртуальный путь.
- `vfs.VirtualFileSystem.read_file`: возвращает байты файла из памяти.
- `vfs.VirtualFileSystem.summary`: считает каталоги, файлы и размер данных.
- `vfs.VirtualFileSystem.describe`: описывает файл либо содержимое каталога.

## Структура и история этапов

`src/` содержит исходный код, `tests/` - автоматические проверки,
`examples/` - команды эмулятора, `scripts/` - демонстрационные скрипты ОС.
`run.sh` запускает приложение из любой рабочей директории.

Первый этап сохранён коммитом `feat(repl): implement variant 19 stage 1
shell prototype`; второй - `feat(config): implement variant 19 stage 2
startup configuration`; третий - `feat(vfs): implement variant 19 stage 3
in-memory directory snapshot`.
Посмотреть историю: `git log --oneline -- pract1ind`.
